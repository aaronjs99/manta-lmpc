# Recoverable Manta simulation runs

The Manta workflow generates an APF seed (iteration 0), runs the requested
number of LMPC iterations, and renders the selected valid trajectory. Every
completed iteration now saves `checkpoint.npz` and updates `summary.json`.
There is no hardware connection in this workflow.

## Start, inspect, and continue

From the repository root, generate a baseline without running the optimizer:

```sh
python run.py baseline --scenario manta_crossover --no-video --output-dir results/tmp/my_manta_run
```

Continue that run to a total of two LMPC iterations:

```sh
python run.py --resume results/tmp/my_manta_run --iterations 2 --no-video
```

`--iterations` is the total target, not a count of additional iterations.
A run with iteration 1 already completed and `--iterations 3` executes only
iterations 2 and 3. The same command works through `scripts/run.py` and
`python -m scripts.run`. `--resume` also accepts the checkpoint file itself.

Resume uses the effective settings stored in the checkpoint, including the
original command-line overrides. It does not reread the mutable YAML file.
Only the total iteration target, verbosity, video setting, and output location
may change. Explicit numerical overrides or `--config` are accepted only if
their scenario, plant, APF, and LMPC settings match the saved run.
Start a new run to change those settings.

To extend a saved run while preserving its directory, use a separate empty
destination:

```sh
python run.py --resume results/tmp/my_manta_run --iterations 3 --no-video --output-dir results/tmp/my_extended_run
```

If all requested iterations are already complete, resume regenerates the
reports without running APF or the optimizer. For example, add `--make-video`
to create the GIF from a completed checkpoint.

## Stop and recover

Use Ctrl+C, or create `STOP_RUN` inside the printed run directory. An explicit
`--stop-file` uses the given path, relative to the invoking working directory.
Stop files belong to the caller: startup and cancellation never delete them.
Remove the stop signal before continuing the run.

Cancellation exits with code 130 and preserves all completed iterations.
The active, unfinished iteration is discarded and starts again on resume.
If APF generation was not yet complete, there is no seed to recover. Stop
signals are checked between APF candidates and during every LMPC step.

Checkpoint replacement is atomic and uses no pickle data. If saving is
interrupted, the preceding checkpoint remains available. A damaged archive,
unsupported version, inconsistent array shape, or nonfinite state/control
produces an error instead of continuing with questionable data. Admission
verdicts are recomputed from stored states and statuses on load. Safe but
incomplete trajectories remain available as diagnostics and are never used
as the learned seed.
If no APF candidate completes safely, a diagnostic checkpoint is retained and
LMPC stops before constructing the optimizer. Increase `--apf-max-steps` or
adjust the scenario in a fresh run to obtain a usable seed.

A fresh run refuses a nonempty output directory. `.manta-run.lock` prevents
two processes from writing to the same run. Normal completion, handled
failure, and Ctrl+C release the lock. If a hard process kill leaves it behind,
confirm that the process named in the lock has stopped before removing that
one lock file and resuming. Never remove another active run's lock.

## Outputs and interpretation

- `checkpoint.npz`: the recovery authority, containing effective settings,
  APF controls, complete histories, LMPC controls, solver slack, and statuses.
- `summary.json`: current progress and validation metrics. `iterations` is the
  requested target; `completed_iterations` is the saved LMPC count.
  `run_status` is `running`, `reporting`, `completed`, `interrupted`, or `failed`.
- `summary.json.artifacts`: paths generated by the current completed report.
  During execution or after interruption this mapping is empty. A previously
  generated GIF is preserved when resuming with `--no-video`, but its current
  report entry is `null`; that existing file may depict an earlier iteration.
- `states_by_iteration.csv`, four PNG diagnostics, and the optional
  `final_iteration.gif`: generated after the requested simulation finishes.

`run_status: completed` means the requested computation and reports finished;
trajectory validity and solver cleanliness have separate fields. A selected
APF seed can remain the best valid result when later LMPC iterations fail to
reach every goal. Inspect `validation_by_iteration`, `selected_iteration`,
and both the fallback and safety-intervention counts.

The JSON summary and plots may lag a checkpoint after a hard kill or rendering
failure. Resume reads the checkpoint and regenerates them. The archive retains
floating-point data exactly, but different solver/library versions or machines
can produce different later solves. Simulation validation is not physical
validation.

## Development verification

Python callers can use `run_manta_lmpc(..., resume_result=previous_result)` with
the original numerical settings and a larger iteration target. Results retain
their numerical provenance; both direct resume and saving a real result under
a different configuration reject mismatches. Archive loading reconstructs this
provenance from the saved effective configuration.

The focused suite uses standard-library unittest and the installed numerical
dependencies; no additional testing dependency is required:

```sh
python -m unittest discover -s tests -v
python -m compileall -q scripts tests
python -S run.py --help
```

Run checks in a temporary output directory to preserve `results/latest/`.
